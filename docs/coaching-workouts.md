# 수업 기록과 운동 과제

## 사용 흐름

- 회원: 예정 수업의 **수업 기록 · 대행 허용**에서 해당 수업 기록을 허용한다. 건강정보 열람 동의와는 별개다.
- 트레이너: 코칭 캘린더의 **수업 운동 기록**에서 회원 이름과 예약 시간을 확인하고 종목·세트를 입력한다. 담당 관계와 승인, 회원 동의, 실제 예약 시간은 서버가 매 저장마다 확인한다.
- 트레이너: 회원 상세의 **운동 과제 관리**에서 날짜·운동·코치 메시지를 보낸다. 센터 담당 회원과 개인 코칭 연결 회원 모두 지원한다.
- 회원: 홈의 **트레이너의 운동 과제**에서 시작하고, 기록한 결과는 트레이너에게 보인다. 새 과제와 최초 완료는 앱 알림함으로 안내한다.
- 과제함의 알림 설정에서 회원이 켜면 한국 시각 6~22시 중 선택한 시간에 미완료 과제를 하루 한 번 안내한다. 기기 푸시는 기존 알림 설정·기기 권한을 따른다.
- 과제를 건너뛰거나 취소해도 수행한 세트는 일지에 남는다. 완료된 과제는 취소할 수 없으며 회원이 세트를 되돌려 수정할 수 있다.

대면 수업과 수업 밖 과제를 지원한다. 서버 저장에는 연결이 필요하다. 통신 실패 시 현재 편집 화면에서 입력을 보존하고 같은 요청으로 재시도하며, 앱 종료까지 보장하는 오프라인 저장 기능은 아니다.

## 저장 및 접근

`CoachingWorkoutRepository`가 도메인 포트이며 `SupabaseCoachingWorkoutRepository`만 Supabase를 안다. 새 어댑터를 벤더 격리 검사 허용 목록에 등록한 이유는 코칭 원본과 개인 스냅샷의 저장 책임을 분리하기 위해서다.

`coaching_workouts`를 원본으로 사용하고 개인 `app_state_snapshots`에는 코칭 종목을 넣지 않는다. `AppState`가 회원 본인의 일지·캘린더·통계에 원본 복사본을 합치고, 이 종목은 전용 기록 화면에서만 고친다. 개인 데이터 동기화나 같은 날짜 개인 운동 삭제가 코칭 기록을 덮어쓰지 않는다. 명시적으로 다른 날짜에 복사한 운동은 완료 여부를 초기화한 개인 계획이다.

과거 이력 RPC는 기존 수업별 건강정보 동의와 접근 로그를 유지하면서 개인 기록과 모든 트레이너의 과거 코칭 기록을 날짜·UUID 순으로 합친다. 수업 대행 편집은 해당 수업 원본에만 적용하며 과거 개인 기록은 조회한다.

클라이언트의 버전과 서버 버전을 비교하고, 요청 UUID를 사용자·동작·내용에 묶는다. 재시도는 중복 저장·중복 알림을 만들지 않는다. 충돌 시 미저장 입력과 최신 기록을 비교한 후 사용자가 전환한다. 수업 동의 및 기록 변경은 이벤트 테이블에 남는다. 로그아웃 이후 도착한 응답은 이전 계정 정보로 화면을 복구할 수 없다.

알림은 `private.enqueue_push`로 알림함과 outbox에만 넣는다. `setflow-coaching-workout-reminders` 크론은 10분마다 미완료 과제와 회원 설정을 확인하고 날짜별 중복을 막는다. 전송은 기존 outbox 발송기가 처리한다.

## 상담에서 이어지는 기록 관리

회원과 트레이너는 상담 상세의 **트레이너 연결 및 기록 관리**에서 연결을 요청한다. 상대도 동의해야 활성화되며, 상담 신청·기존 초대·센터 배정만으로 전체 기록 편집 권한을 부여하지 않는다. 회원은 **운동 장소 및 센터 → 트레이너 연결과 기록 승인**, 사업자는 **회원 목록 → 운동 관리 연결과 수정 요청**에서 관리한다.

한 트레이너는 여러 회원과 각각 연결할 수 있다. 같은 트레이너·회원 조합의 중복 연결만 막으며, 회원별 상담과 기록 권한은 분리한다. 개인 코칭 초대 링크는 한 회원만 수락할 수 있으므로 **다른 회원 초대**로 회원마다 새 링크를 만든다. 기록 관리의 **승인 대기**에서는 본인의 수락이 필요한지 상대의 수락을 기다리는지 안내한다. 관리 화면을 닫으면 회원 목록을 갱신해 새로 활성화된 연결을 표시한다.

`CoachingManagementRepository` 포트가 연결 요청·응답·해제, 업장 공유, 담당 변경 요청, 전체 이력 조회와 기록 정정을 제공한다. `20261001063252_coaching_management_consent.sql`을 앱과 함께 적용해야 한다. 기존 수업 대행 입력/건강정보 동의는 별도로 유지한다.

개인 기록을 정정받은 계정은 `correctionVersions`를 보존하는 새 앱을 사용해야 한다. 구버전의 오래된 전체 저장은 정정 내용을 덮어쓰지 않도록 서버에서 거부한다.

- 활성 연결의 트레이너는 연결 전을 포함한 개인 운동·수업·과제 기록을 페이지 단위로 조회한다. 기기에만 남아 있는 게스트 기록은 공개되지 않는다.
- 수업과 개인 운동 모두 종료 후 **48시간 미만**에는 세트의 무게·횟수·휴식·시간·거리·RPE·RIR을 직접 정정할 수 있다. **정확히 48시간부터** 회원 승인이 필요하다. 종료 시각이 없는 오래된 기록은 승인 대상으로 처리한다. 수업은 일정의 종료 시각과 완료 시각 중 이른 시각을 쓴다.
- 기존 개인 기록의 시간대 없는 종료 문자열은 수업 일정과 같이 한국 시각으로 해석한다. 시간대가 명시된 기록은 그 시각을 그대로 사용한다.
- 수업 기록 생성 시 종료 기준을 보관하고 조기 완료 시에만 앞당긴다. 지난 일정의 날짜·시간 변경이나 완료 취소로 수정 가능 시간을 다시 열 수 없다.
- 수정 요청은 전후 값과 이유를 보관한다. 승인은 해당 변경 한 건에만 적용되고, 원본 버전이 바뀌었으면 `conflict`로 남기며 반영하지 않는다. 연결 해제는 대기 요청을 취소한다.
- 개인 기록 정정은 원본 스냅샷과 정규화된 세트를 같은 트랜잭션에서 갱신한다. 세션의 `correctionVersions`로 오래된 기기의 전체 저장을 검사하고, 동기화 충돌에서는 미확인 정정 항목만 병합해 다른 오프라인 세트·값을 보존한다. 이미 확인한 정정은 회원이 다시 수정할 수 있다.
- 회원이 실제 소속 업장을 선택해 공유하면 해당 업장 소유자가 전체 기록·담당자·정정 이력을 조회한다. 단순 운동 장소 등록은 권한이 아니다. 업장에는 정정·수정 승인 권한이 없다. 담당 변경 요청은 새 트레이너와 회원이 모두 수락해야 기존 기록 관리 연결을 대체한다. 수락 전에 기존 연결은 유지된다.
- 공유 철회·소속 종료·트레이너 승인 취소를 매 RPC에서 검사한다. 알림은 `private.enqueue_push`를 통해 보관하며, 푸시와 알림함 모두 `coaching_management` 이벤트로 같은 화면을 연다.

관리 연결의 해제는 이 연결에 추가로 부여한 전체 기록 권한을 종료한다. 별도로 동의한 수업별 공유나 기존 센터 배정 자체는 각각의 관리 화면에서 해제한다.

## 검증

`flutter test`에 코칭 화면, 개인 원본 분리, RPC 직렬화, 알림 진입 회귀가 포함된다. 화면은 320px 너비·글자 크기 2배도 검사한다.

SQL은 PGlite 설치 경로를 전달해 실행한다:

```sh
node tool/test_coaching_workouts.mjs /path/to/node_modules/@electric-sql/pglite
node tool/test_coaching_management.mjs /path/to/node_modules/@electric-sql/pglite
```

예약 시간 전·중·후, 동의 철회, 담당자/타인/센터 관계, 버전 충돌과 재시도, 취소 후 이력, 알림 중복, 전체 운동 이력 페이지 경계를 실제 SQL로 검증한다. 실제 회원 데이터와 기기에는 테스트 알림을 보내지 않는다.
