# 09 · 함께(게임방) 보강 계획

> 2026-09-02. "지금 함께가 일반적으로 게임방으로 하는 느낌이 없어" — 런칭 전에
> 게임 방의 상식(방제·방장·강퇴·멤버 소셜)과 기록↔방 동기화를 갖춘다.
> 함께의 설계 원칙(시각 기반 동기화·서버가 차례 결정·포트 스트림)은
> `lib/data/together_repository.dart` 헤더와 `docs/backend-portability.md`가 정본.

## 0. 현황 (2026-09-02, 1.14.13)

- 방 = 코드/근처로 모여 전광판(LED)으로 겨루는 공유 타이머. 종목 3(헬스·크로스핏·교대).
- 공개/비밀 + GPS 근처 목록(실시간 구독), 초대 링크, 12시간 유휴 정리 크론.
- **없는 것**: 방제, 방장 표기, 강퇴, 멤버 프로필/DM/팔로우.
- **버그**: 기록 탭에서 세트를 완료하면 방 전광판에 반영되지 않음
  (보고 경로가 방 안의 "세트 끝냈어요" 버튼뿐).

## 1. 이번에 하는 것 (P0 — 런칭 필수)

### 1-1. 기록 ↔ 방 동기화 (버그)
- **원칙: 세트 완료가 곧 방 보고다.** 보고를 화면(방 버튼)이 아니라
  `AppState.toggleSet`으로 내린다 — 완료가 오늘 세션이고 `activeTrainingPartyId`가
  있으면 `reportSetDone`(fire-and-forget). 기록 탭 스와이프·방 버튼·어디서 완료해도
  전광판이 같은 숫자를 본다.
- 방 버튼은 toggleSet + 전파(adopt)만 남긴다(보고 중복 금지).
- 한계(알고 감): 완료 취소는 서버 카운트를 되돌리지 않는다(기존과 동일).
  보고 실패는 조용히 버린다 — 다음 보고가 누적 볼륨을 다시 실어 나른다.

### 1-2. 방제 (제목)
- DB: `training_parties.title text`(nullable, 24자 제한). `create_training_party`에
  `p_title` 추가, 방 JSON·근처 목록 JSON에 `title` 포함.
- 만들기 시트 맨 위에 방제 입력(선택, 비우면 기본 없음). 앱바 제목·근처 목록 줄이
  방제를 우선 표시(없으면 기존 규칙: "지훈님의 방" / "공개 · 헬스 · 2명").

### 1-3. 방장 표기 + 강퇴
- 방장 = `host_user_id`(이미 있음). 전광판 줄에 "방장" 라벨.
- 강퇴: RPC `kick_training_party_member(p_party_id, p_member)` — 방장만, 자신 제외.
  쫓겨난 쪽은 방 스트림이 끝나며 로비로(기존 소멸 처리 재사용) + 안내 한 줄.
  방장 UI: 전광판 멤버 줄 롱프레스 → 시트(강퇴). 나간 사람과 동일하게 차례 승계.
- 방장 승계: 방장이 나가면 남은 멤버 중 turn_order 최솟값이 방장(서버 leave RPC 보강).

## 2. 후속 (P1 — 방 멤버 소셜)

> 별도 스키마가 필요해 이번 범위에서 뺀다. 방향만 정본으로 확정.

- **프로필 보기**: 전광판 줄 탭 → 멤버 미니 프로필 시트(닉네임·오늘 세트·팔로우 버튼).
- **팔로우**: `follows(follower_id, followee_id)` + RLS(본인 행만 쓰기).
  커뮤니티 피드와 연결(팔로우한 사람 글 우선)이 실효가치 — 커뮤니티 개편과 같은
  마일스톤으로 묶는다.
- **DM**: `dm_threads`/`dm_messages` + Realtime + 푸시(outbox 경유, push-notifications.md
  패턴). 신고/차단 없이는 열지 않는다(모더레이션 선행 — P1의 후반).
- 공개방은 "이름만 보여요" 약속을 지킨다 — 프로필 시트도 닉네임+오늘 기록까지만.
