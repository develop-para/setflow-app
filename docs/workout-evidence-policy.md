# 운동 기록·추천의 근거 검토 정책

검토일: **2026-10-14**. 운동 기록의 모든 설계에는 확인한 연구 원칙 또는 구체적인 운영·사용성·데이터 이유를 남긴다.
논문에 없는 수치를 DOI가 있다는 이유만으로 연구 결론처럼 설명하지 않는다. 기록을 반영한 알고리즘과
개인별 최적량·회복·안전성을 검증한 알고리즘도 구분한다.

## 변경할 때 함께 검토할 것

1. `lib/domain/workout_design_rule.dart`에서 해당 판단을 등록·갱신한다. 연구 원칙, 실제 구현,
   수치·동작의 선택 이유, 적용 한계, 연결 출처와 검토일을 함께 읽는다.
2. 출처는 `lib/data/evidence_catalog.dart`의 공식 논문·가이드라인 링크로 확인한다. 원문의 대상,
   비교 조건과 결과가 앱의 주장에 적용되는지 확인하고 초록만 봤는지 본문까지 봤는지도 남긴다.
3. **연구에서 확인한 원칙 / 앱이 선택한 수치 / 관찰한 개인 기록 / 시간·입력 추정 / 사용자 선택**을 구분한다.
   연구가 필요 없는 저장·입력·되돌리기 동작에는 실제로 필요한 이유를 쓴다.
4. 연결된 계산·화면·저장 회귀를 갱신하고 실행한다. 과거 기록·RIR·계정 소유권이 유지되는지도 확인한다.
   계산이 코드대로 실행된다는 테스트와 사용자에게 더 효과적이라는 실증은 별개다.
5. 근거가 약하거나 없는 수치를 고정하려면 필요한 이유와 한계를 먼저 설명한다. 논문이 입증하지 않은
   개인별 최적값·운동 종료 지시·안전 경계·부상 예방 효과로 포장하지 않는다.

## 원문 확인일과 이번 검토 범위

아래 공식 출처의 **초록을 2026-10-14에 다시 확인**했다. 전체 논문의 모든 분석이나 부록을 재현한 검토는 아니다.
메타분석·가이드라인의 집단 결과를 이 앱의 정확한 숫자와 개인 처방 효과로 바꾸어 해석하지 않는다.

이번 검토에서 이들 논문의 본문 전체를 새로 검증했다고 주장하지 않는다. 새로운 정확도·효과·위험 감소 주장을
추가할 때는 그 주장에 해당하는 원문 부분을 다시 확인해야 한다.

## 추가 문헌 검색과 선정: 2026-10-14

이번 검색은 앱의 빈 근거 영역을 찾는 **목적을 정한 문헌 재검색**이다. 독립적인 체계적 문헌고찰이나
모든 연구를 빠짐없이 수집했다는 주장이 아니다. PubMed와 공식 저널 사이트를 사용했고, 2024–2026년
체계적 고찰·메타분석을 우선했다. RIR 예측 정확도와 자율조절의 직접 근거는 2022년 논문도 비교했다.
검색 주제는 `inter-set rest interval hypertrophy systematic review`, `proximity to failure RIR meta-regression`,
`repetitions in reserve prediction accuracy`, `resistance training load volume autoregulation`,
`per-session volume frequency distribution hypertrophy`, `mHealth resistance training meta-analysis`였다.

선정은 출판연도나 인용 수가 아니라 **현재 규칙과 직접 연결되는지, 기존 출처에 없는 정보를 보완하는지**로 판단했다.
대상·중재·결과가 겹치는 고찰은 서로 독립적인 새 참가자 자료처럼 합산하지 않는다. 기존 Refalo·Larsen·Pelland와
추가 메타분석 사이에 같은 원연구가 포함될 수 있으며, 논문 다섯 편을 추가했다는 이유만으로 확신도를 다섯 배로 높이지 않는다.

본문 일부를 읽은 범위는 위 표와 같으며 원자료·모든 부록·분석 코드를 재현하지는 않았다.

**보류한 출처와 이유:** Petro 2025의 RPE·움직임 속도 타당성 고찰은 참고할 수 있지만 현재 RIR 안내에는
실제 남은 반복수와의 오차를 다룬 Halperin이 더 직접적이어서 중복 추가하지 않았다. 2026년 고부하·저부하의
비특이적 근력 메타분석은 등척성·등속성 전이 결과로 현재 종목별 부하 판단의 직접 근거가 아니다.
대상이나 동작이 좁은 신규 운동량 RCT·서술 고찰도 자동으로 새 상한을 만들기 위해 추가하지 않았다.
세션별 운동량·분산은 기존 Pelland 2026·Ramos-Campo 2024를 함께 보고, 하루 숙련 8세트 제한을
논문이 입증한 경계라고 해석하지 않는다.

**수치 알고리즘은 유지한다.** 이번 추가 논문은 정확한 일일 세트·RIR 2–3·휴식 초·주간 ±2세트의 개인 최적성을
검증하지 않았다. 출처 연결과 설명을 보강하며, 실제 수치 변경은 별도의 적용 이유와 계산·화면·데이터 회귀가 필요하다.

## 저항운동 숫자별 원칙·운영 이유·한계

계산 위치는 `ResistancePrescriptionEngine`, `PersonalCoachingEngine`, `PerformanceEngine`이다.
아래 이유는 **앱의 설계 이유**이며 이 숫자를 논문이 검증했다는 의미가 아니다.

|---|---|---|---|
| 부위별 하루 4/6/8, 근비대 주간 8/12/16, 그 외 주간 6/10/10, 하루 전체 12/18/24세트 | 주간 운동량과 훈련 경험을 고려 | 정보가 부족한 상태에서 세트 완료 때마다 새 운동을 끝없이 자동 제안하지 않는 시작 계획 | 수치 간격은 제품 선택이며 개인별 최적량·생리적 상한이 아니다. 명시적 추천 요청은 계획을 넘어 진행할 수 있다. |

| 같은 종목 최근 작업세트의 최빈 중량, 동률이면 낮은 값 | 그 종목의 실제 수행 | 다른 기구 kg이나 수행하지 않은 중량을 만들어 넣지 않음 | 최빈 중량이 최적 중량이라는 뜻은 아니다. 기록 없으면 직접 선택한다. |
| 28일 이내 두 날짜의 반복 상단 달성 후 증량, 증가폭 10% 이내 | 점진적 과부하와 반복 관측 | 한 번의 좋은 수행으로 중량이 급변하지 않게 함 | 두 날짜·28일·모든 세트 상단·RIR 조건의 조합은 앱 판단이다. |
| 증량 단위 0.5/1/2.5/5kg | 실제 기구 조작 단위의 필요 | 작고 기록 가능한 단위로 변경 | 단위는 장비마다 다르며 논문이 정한 개인 증분이 아니다. |
| 두 날짜마다 최소 두 세트가 최소 반복 미달이면 약 5% 기준 조정 | 반복된 수행 미달 | 한 세트의 우연한 실패에 반응하지 않음 | 두 날짜·두 세트·5%는 앱 선택이며 피로나 과훈련 진단이 아니다. |
| 오늘 피로 응답에는 1세트·약 10% 기준 중량 조정 | 당일 입력과 수면 부족의 수행 저하 가능성 | 현재 입력한 상태를 새 시작 계획에 반영 | 모든 피로를 측정한 것이 아니고 정확한 감량 폭·부상 감소 효과는 검증되지 않았다. |
| 동일 종목 28일 초과 공백에는 1세트·약 10% 기준 조정 | 해당 종목 기록의 오래됨 | 오래된 수행을 현재 능력으로 단정하지 않음 | 다른 운동까지 중단했다는 판단이나 28일이라는 생리적 경계가 아니다. |
| 중량 감량 뒤 0.5kg 단위 내림, 0kg이 되면 기존 양수 유지 | 표시·조작 단위 | 적용 가능한 kg을 제시하고 실제 기록 중량이 임의로 0kg이 되는 것을 방지 | 실제 변화율은 5/10%와 다를 수 있어 전후 kg을 표시한다. 장비에서 가능한지는 사용자가 확인한다. |
| 42일 안 네 날짜, 같은 중량·같은 세트 수에서 평균 반복이 세 번 연속 ≥1회 감소하면 1세트 감소 | 비교 가능한 수행 추세 | 중량·세트 수 차이로 평균이 바뀌는 혼동을 일부 줄임 | 네 날짜·42일·1회·1세트는 앱 판단이며 전신 회복·질환 진단이 아니다. |
| 네 날짜의 평균 반복 차이 ≤1이면 정체 표시·중량 유지 | 동일 중량의 반복 변화 | 불필요한 자동 증량을 보류하고 기존 목표를 재시도 | 근육 증가나 모든 근력 발달이 멈췄다는 뜻이 아니다. |
| RIR 2–3 안내, 증가 조건에 기록된 RIR 2 이상·10 이하 | 실패 근접도 연구와 주관적 예측 오차 | 수행 여유를 사용자가 기록한 경우 증가 판단에 활용 | 특정 RIR이 모두에게 최적이라는 결론이 아니다. 정확한 실측값이 아니며 평균 예측 오차를 자동 보정하지 않는다. 10은 입력 범위이며 생리적 경계가 아니다. |
| 같은 중량의 기존 세트별 +1회, 휴식 차이 ≤15초 | 점진적 수행 목표와 비교 조건 | 무게를 유지할 때 작은 목표를 주고 세트별 수행 차이를 보존 | +1회·15초는 앱 선택이다. 설정 휴식은 실제 측정 휴식이 아니다. RIR 미입력은 여유를 확인했다는 뜻이 아니다. |

| 수치·판정 | 관찰·운영 이유 | 적용 한계 |

| 운동한 주의 평균 완료 세트 수 | 최근 실제 수행량 가까이에서 새 계획을 시작 | 과거 수행량이 적정량·최적량·회복 가능한 최대량이라는 증거는 아니다. |
| 같은 종목 최근 3일·같은 중량·2–3세트·설정 휴식 차이 ≤15초 | 비교 조건을 일부 맞추고 세트 추가로 평균이 낮아지는 혼동 방지 | 가동범위·동작 품질·실제 휴식·속도를 모두 통제하지 못한다. |
| 두 구간 연속 평균 +1회·모든 종목 비교 가능·실제 RIR ≥2이면 주간 +2세트 | 수행과 기록된 여유가 있을 때 작은 변경을 제안 | 이미 향상 중인 사람에게 세트를 늘리는 것이 유지보다 낫다는 직접 검증이 아니다. |

| 주간 계획 최소 4·최대 12/20/24, 빈도 1–3회·선택한 운동일 이내 | 작은 변경으로 최근 수행량과 실제 가능한 날짜에 맞춤 | 제품 계획 범위이다. 보조근이 쓰인 날도 빈도에 포함하므로 직접 운동 빈도와 다를 수 있다. |
| 하루 계획=주간/빈도 올림, 최소 2·입문 최대 6·그 외 최대 10세트 | 주간 계획을 기록 가능한 세션으로 나눔 | 개인의 하루 생리적 상한이 아니다. |
| 종목별 최근 실제 세트 수를 2–5세트로 사용, 증가 신호면 +1 | 개인 기록 가까이에서 새 계획을 제시 | 정확한 2–5·+1 조합의 최적성을 검증하지 않았다. 증량·피로·복귀·하락 때 세트 증가를 겹치지 않는다. |

## 유지해야 할 UX·데이터 동작

- **계획과 관찰을 구분한다.** 완료 기록·실제 RIR을 새 추천이 덮어쓰지 않는다. 다른 날짜의 새 계획으로 복사할 때
  완료 상태·실제 RIR을 새 수행처럼 옮기지 않는다. 기록 정정용 사본은 원래 관찰값을 보존한다.
- **명시적 요청과 자동 제안을 구분한다.** 사용자가 **운동 추천**을 누르면 기본 계획 안팎에서 바로 제안한다.
  기본 계획을 넘었다는 이유로 확인 창을 먼저 띄우지 않는다. 자동 완료 후 추천은 기본 계획에서 멈춘다.
  최종 제안 세트가 남은 계획을 넘는 경우에만 추가 요청임을 표시하고 허용 상태는 설정에 저장하지 않는다.
- 추가 요청에도 장비·부위·통증 응답·제외 동작·제외 종목·시간 조건은 적용한다. 다른 부위로 몰래 풀거나
  건너뛴 종목을 허락 없이 복원하지 않는다. 조건에 맞는 운동이 없으면 이유와 실제 수정 경로를 제공한다.
- 숫자 편집은 다이얼의 **적용**에서 저장하고, 실제 기록을 뒤의 미완료 세트에 전파하면 되돌릴 수 있어야 한다.
  완료 기록·후속 수동 수정·더 무거운 계획은 보존하며 관찰값인 RIR은 전파하지 않는다.
- 첫 미완료 세트부터 완료한다. 완료한 세트는 접어서 남기고 다시 수정·되돌릴 수 있게 한다.
  휴식 종료 시각을 기준으로 이동·백그라운드·복귀에도 시간을 유지한다. 새 세트 시작 외에는 자동으로 창을 펼치지 않는다.
- 게스트 기록도 기기에 저장하고 계정 소유권을 섞지 않는다. 로그인했다는 이유만으로 게스트 기록을 자동 소유 처리하지 않는다.
- 운동 중에는 설명·설문·확인을 자동으로 끼워 넣지 않는다. 근거 설명은 사용자가 열어 볼 수 있게 하고
  숫자 수정·다음 세트 완료·휴식 조작 경로를 가리지 않는다. 작은 화면·2배 글자·다크 모드·세이프에리어를 유지한다.

## 검증과 자동 검사의 범위

- 계산: `test/resistance_prescription_test.dart`, `test/exercise_recommendation_result_test.dart`,
  `test/personal_coaching_test.dart`, `test/cardio_prescription_engine_test.dart`, 성능·반복 목표 관련 회귀.
- 화면: `test/exercise_library_recommendation_test.dart`, `test/recommendation_volume_week_flow_test.dart`,
  `test/advanced_recommendation_flow_test.dart`, `test/personal_coaching_flow_test.dart`,
  `test/recommendation_profile_screen_test.dart`, 세트 편집·휴식·접근성 관련 회귀.
- 보존·계정: `test/account_persistence_test.dart`, 개인 스냅샷·게스트 재시작·RIR·유산소 저장 관련 회귀.
  등록부의 출처 연결·필수 설명과 아키텍처 표현 회귀도 함께 검토한다.
- `tool/architecture_rules.dart`의 새 표현 규칙은 운동 관련 화면·엔진·`AppState`에서
  `(권장|최적|안전) 운동량 (한도|상한)`류 문구를 금지한다. 예외 목록으로 우회하지 않는다.
  **특정 문자열 검사일 뿐 연구의 질·임상 타당성·개인 안전성·표현 전체를 판정하는 도구가 아니다.**
  이 표현이 없어도 과장이 있을 수 있으며 원문 검토가 필요하다.
- 회귀 통과는 구현의 동작과 데이터 보존을 확인한다. 이 앱 알고리즘의 임상 효과·부상 감소·개인별 최적성이나
  실제 기기 전체에서의 결과를 입증하지 않는다. 이번 변경도 사용자 기록으로 얻지 않은 정보를 새로 만들어 저장하지 않는다.

구현의 세부 흐름은 [운동 추천](workout-recommendations.md), 개인 계획 계산은
[개인 코칭](personal-coaching.md)을 따른다. 숫자나 적용 방식을 바꾸면 이 표·등록부·관련 회귀도 함께 갱신한다.
