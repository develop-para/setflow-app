# 상담 채팅

회원은 코칭 탭의 진행 중 상담이나 상담 이력을 열어 같은 방에서 질문을 이어 보낸다. 트레이너와 센터는 상담 수신함에서 대화한다. 상담 정보 버튼으로 신청 내용, 공유한 설문, 운동 기록 관리와 담당 트레이너 배정을 확인한다.

메시지는 시간순 말풍선으로 표시하며 새 답변은 자동으로 수신한다. 이전 메시지를 읽고 있으면 스크롤을 이동시키지 않고 **새 메시지 보기**를 표시한다. 알림함과 푸시 알림은 동일한 상담방으로 연결된다. 회원이 추가 질문을 보내면 업무 수신함에서 미답변으로 다시 표시한다.

`ConsultationChatRepository`가 조회·전송·도메인 스트림을 제공하고, Supabase 어댑터만 테이블과 Realtime을 안다. Realtime 이벤트 뒤에는 접근 정책이 적용되는 원본을 다시 읽고, 연결 누락에 대비해 주기적으로 갱신한다. 발신 역할과 담당 관계는 서버가 판단한다.

운영 서버에는 `20261001070634_consultation_chat.sql`을 적용했다. 신규 전송 RPC와 두 상담 테이블의 Realtime 발행 등록을 앱과 함께 반영한다.

전송 실패 시 화면의 입력 내용과 요청 UUID를 유지한다. 같은 내용의 재시도는 메시지와 알림을 중복 생성하지 않는다. 앱을 닫은 뒤에도 미전송 초안을 보관하는 기능은 제공하지 않는다. 로그아웃·계정 변경·접근 권한 변경 시 이전 대화와 입력을 화면에서 제거한다.

알림은 기존 `private.enqueue_push`를 통해 알림함과 발송함에 함께 남는다. 클라이언트는 알림을 직접 전송하지 않는다. 해당 상담의 회원, 승인된 현재 담당 트레이너, 인증된 담당 센터가 조회·전송할 수 있다. 관리자의 기존 상담 조회 정책은 유지한다.

채팅 화면과 알림 진입은 Flutter 위젯 테스트로, 메시지 권한·재시도·추가 질문 상태·알림 저장은 `tool/test_consultation_chat.mjs`에서 실제 SQL로 검증한다.
