# 개인 코칭 베타

기록 메뉴 → 시간·추천 설정 → **개인 코칭 (베타)** → **개인 코칭 추천 사용**에서 켠다.
베타는 게스트도 무료로 사용한다. 기록·루틴·캘린더·통계와 기본 추천은 기존대로 사용할 수 있다.
설정은 기존 `RecommendationPreferences`에 저장하며 기기 재시작·계정 동기화·명시적인 게스트 가져오기를 따른다.
기존 운동 계획·완료 기록을 자동 수정하지 않고 새 추천에만 적용한다.

## 계산 규칙 v1

`PersonalCoachingEngine`이 계획을 만들고, `ResistancePrescriptionEngine`과
`ExerciseRecommendationEngine`이 같은 계획으로 수치와 후보를 계산한다. 외부 AI 호출은 없다.

- 주간 목표는 월요일을 기준으로 **직전 3개 완료된 달력 주**를 본다. 같은 주의 추가 운동은
  예산을 소모하지만 자기 목표를 늘리지 않는다. 기록을 수정하거나 목표·경험·주간 운동일 설정을
  바꾸면 다시 계산한다.
- 일반 완료 세트만 개인 기준량을 정한다. 웜업·예시·미완료·미래 기록은 제외한다.
  주동근 1, 검토된 보조근 0.5로 집계한다. 같은 날짜·종목의 여러 행은 하나의 수행일로 합친다.
  같은 운동 행 ID의 사본은 중복 집계하지 않는다.
- 최근 3주 중 2주 이상에 해당 부위 주동근 기록이 있고 최소 4일, 가장 최근 주에도 수행이 있어야
  개인 운동량을 계산한다. 부족하면 숙련도별 기본 예산을 유지하고 부족한 이유를 표시한다.
- 운동한 주의 평균 세트 수를 기준으로 삼는다. 비교는 동일 종목의 최근 3일, 같은 중량,
  최소 2개의 일반 세트, 같은 수의 비교 세트(최대 3), 설정 휴식 평균 차이 15초 이내로 제한한다.
  설정 휴식은 실제 휴식의 측정값이 아니다. 부분 기록이나 시간 버티기로 반복수 추세를 만들지 않는다.
- 두 구간에서 평균 반복이 각각 1회 이상 개선된 종목이 있고, 그 부위의 모든 종목에 비교 가능한 기록과
  비교 중량 세트의 RIR 2 이상 기록이 있으면 주간 목표를 2세트 늘린다.
  RIR 미입력은 여유가 있다는 증거로 간주하지 않는다.
- 해당 부위의 서로 다른 2개 이상 종목에서 평균 반복이 두 구간 연속 1회 이상 줄면 목표를 2세트 줄인다.
  단일 종목의 하락을 전체 피로나 통증의 진단으로 확대하지 않는다.
- 개인 주간 목표는 최소 4, 입문 최대 12·기본 최대 20·숙련 최대 24세트다. 부위별 빈도는 최근 실제
  빈도를 반올림하고 1–3회, 사용자가 선택한 전체 운동일 수 이내로 제안한다. 하루 부위별 예산은
  목표/빈도 올림, 최소 2·입문 최대 6·그 외 최대 10세트다. 전체 세션 예산 12/18/24는 유지한다.
- 이번 주 지난 날짜는 완료 작업세트만, 오늘은 미완료 계획도 예약량으로 센다. 기본 추천의 최근 7일과
  개인 코칭의 월–일 집계는 구분한다. 드랍 등 작업세트는 소비량에 포함하지만 개인 비교는 일반 세트만 쓴다.
- 충분한 부위 기록과 해당 종목의 4일 이상 기록이 있고 증량·하락·복귀·오늘 피로 조정이 없으면 최근
  동일 중량의 실제 세트 수를 2–5세트 범위로 사용한다. 주간 증가 근거가 있으면 1세트 더 제안하며
  남은 하루·주간·세션 예산과 시간에 맞춰 줄인다. 중량을 올리는 추천에서 세트도 함께 늘리지 않는다.
- 기존 목표별 반복·중량 조정, 오늘 날짜에만 적용하는 회복 응답, 통증 중단, 장비·제외 동작·부위·시간
  제약은 계속 적용한다. 자동 추천이 끝나도 수동으로 추가할 수 있다.

3주·4일·15초·2세트·세트 상한은 **검증 가능한 앱 기본 규칙**이다. 논문이 개인별 최적값을
확정한 수치가 아니다. 몸의 반응·근육 증가·실제 회복 상태를 운동 로그만으로 확정하지 않는다.

## 근거와 검증 범위

- [Larsen et al., 2021](https://pubmed.ncbi.nlm.nih.gov/33520457/), DOI `10.7717/peerj.10663`:
  수행과 체감 여유에 따라 강도·운동량을 조정하는 접근을 참고했다. 주로 최대 근력에 관한 고찰이며
  이 앱의 규칙이나 근비대 효과를 검증한 연구는 아니다. 앱 근거 목록에도 등록했다.
- 기존 운동량·운동 순서·반복·중량 근거는 [운동 추천 문서](workout-recommendations.md)를 따른다.

회귀는 계산·기록 부족·RIR·중량/휴식 변경·부분/중복 기록·주간 고정·계획 예약·시간/부위 제약·
기기 재시작·계정 권한·로그아웃 경합, 실제 화면 흐름·작은 화면·다크·2배 글자를 검증한다.
테스트 통과는 실제 사용자 효과의 증명이 아니다. 베타에서 제안 수락률, 완료율, 이후 동일 종목 수행,
사용자의 수정량을 확인한 후 규칙을 조정해야 한다. 현재 행동 분석을 외부로 자동 전송하지 않는다.

## 이후 유료 전환

기본 빌드는 `PERSONAL_COACHING_BETA=true`다. 베타 종료 빌드는
`--dart-define=PERSONAL_COACHING_BETA=false`를 사용한다.

`PersonalCoachingRepository.loadMyPersonalCoachingAccess()`가 계정·만료 시각이 담긴 도메인 권한을 반환한다.
현재 어댑터는 `SupabaseRoutineCatalogRepository`다. 권한은 개인 스냅샷에 저장하지 않고 계정 변경·로그아웃·
만료·조회 실패 시 닫는다. 초기 계정 로드와 앱 복귀, 이용권 재확인에서 갱신한다.

서버 준비 파일은 `20261004090000_personal_coaching_access.sql`이다. 현재 베타 사용에는 배포가 필요하지 않다.
유료 전환 전 마이그레이션을 배포하고 `private.personal_coaching_plans`에 허용할 플랜 ID를 서버에서 등록한다.
회원은 이 테이블을 읽거나 쓸 수 없다. 권한 RPC는 `auth.uid()`의 `active` B2C 유료 구독,
미래 `current_period_end`, 서버가 등록한 플랜을 모두 요구한다. 클라이언트가 사용자 ID나 플랜을 전달하지 않는다.

**인앱 결제·상품 ID·영수증 검증·갱신/환불 웹훅은 이번 베타에 연결하지 않았다.** 결제 수신과
`subscriptions` 갱신은 이후 선택한 결제 서비스가 검증한 결과만 서버에서 처리해야 한다.
구독 행을 만들거나 활성화하는 앱 버튼은 없다.
