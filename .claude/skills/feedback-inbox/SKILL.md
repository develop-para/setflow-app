# 요청 사항 보드 처리하기

노션을 읽고 쓰는 일은 전부 `tool/notion_feedback.dart` 한 스크립트가 한다. 노션 MCP로 보드를
직접 만지지 말 것 — 스크립트가 첨부 이미지를 내려받고(노션 첨부 URL은 1시간짜리라 링크만으론
못 본다), 상태·처리 결과·댓글·반영 배포를 형식에 맞게 쓴다.

## 절차

1. **목록** — 완료 아닌 카드가 우선순위(급함→보통→낮음) 순으로 나온다. 카드 id가 같이 찍힌다.
   ```sh
   dart tool/notion_feedback.dart list
   ```
   사용자가 특정 카드를 가리켰으면(제목이나 URL) 그것만, 아니면 위에서부터.
2. **읽기** — 속성·본문·첨부·댓글을 한 번에 본다. 첨부 이미지는 `build/notion-feedback/<id>/`에
   내려받아 경로가 찍히니 **그 파일을 열어서 실제로 본다** (캡처 한 장이 설명 열 줄보다 정확하다).
   ```sh
   dart tool/notion_feedback.dart show <id>
   ```
3. **처리 시작을 알린다** — 코드를 만지기 전에 상태를 진행 중으로. 비개발자에게 "봤다"가 보이는
   시점이 이때다.
   ```sh
   dart tool/notion_feedback.dart update <id> --status 진행중
   ```
4. **처리한다** — 유형에 따라:
   - 버그: 재현 → 원인 → 수정 → 테스트. AGENTS.md 규칙과 `.fry/MEMORY.md`의 함정을 먼저 본다.
   - 기능 요청·개선 요청: 규모가 작으면 바로 구현. 크거나 방향을 정해야 하면 구현하지 말고
     결과에 **선택지와 추천**을 적고 사용자(개발자)에게 묻는다.
   - 질문: 코드로 답을 확인해 댓글로 답한다. 상태는 완료.
   - 정보가 모자라면(재현 안 됨, 기기/버전 없음): `--comment`로 **무엇이 필요한지 구체적으로**
     묻고 상태는 진행 중으로 둔다. "재현이 안 돼요"만 쓰지 말 것 — 어떤 화면에서 무엇을
     눌렀는지, 캡처 한 장을 요청한다.
5. **되돌려 쓴다** — 처리 결과는 요청자 눈높이로 한 줄, 댓글은 요청자에게 하는 말로.
   ```sh
   dart tool/notion_feedback.dart update <id> --status 완료 \
     --result "휴식 타이머가 화면 잠금 뒤에도 이어지도록 고침. 다음 배포에 포함" \
     --comment "확인했어요. 다음 테스트 빌드에서 확인 부탁드려요."
   ```
   배포까지 끝났으면 `--build N`으로 배포 기록 행에 연결한다(배포 기록에 그 빌드 행이 있어야
   한다 — 없으면 스크립트가 거부한다). **코드를 고쳤다고 완료가 아니다** — 커밋·푸시까지 한
   뒤에 완료로 바꾼다. 배포 전이면 결과에 "다음 배포에 포함"이라고 적는다.

## 쓰기 규칙

- 처리 결과·댓글은 **한글**, 존댓말, 기술 용어 없이. "PopScope 수정" (X) / "방에서 뒤로가기를
  누르면 목록으로 돌아가고 방은 유지돼요" (O).
- 요청 하나에 커밋 하나가 원칙. 커밋 메시지에 카드 제목을 인용한다 — 나중에 배포 기록에서
  요청까지 거슬러 갈 수 있게.
- 요청자가 쓴 우선순위·유형이 틀려 보여도 **바꾸지 않는다**. 틀렸다고 판단한 근거를 결과에 적는다.
- 완료 카드는 다시 열지 않는다. 같은 문제가 또 오면 새 카드다.

## 전제

- 토큰: `.env.notion-mcp`(저장소 루트, git 무시됨)의 `NOTION_TOKEN`. 없으면
  `.env.notion-mcp.example`을 복사하라고 안내한다.
- 보드 id: `tool/notion-feedback.json`. 바꾸지 말 것.
- 보드의 카드 속성: 유형(버그/기능 요청/개선 요청/질문) · 우선순위(급함/보통/낮음) ·
  화면 · 기기 · 앱 버전 · 상태(시작 전/진행 중/완료) · 요청자·접수일(자동) ·
  처리 결과 · 반영 배포(배포 기록 관계) · 담당자.
- 카드 본문은 노션 템플릿 양식을 따른다: **무슨 일이 있었나요 → 이렇게 하면 다시 생겨요(번호
  목록) → 이렇게 되면 좋겠어요 → 화면 캡처·첨부**. 비개발자가 칸을 비워 둘 수 있으니 회색
  안내문(예시 문장)이 그대로 남아 있으면 "안 쓴 것"으로 읽는다 — 그 칸의 내용으로 착각하지 말 것.
